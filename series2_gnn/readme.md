# 找qw要一些面试技巧

这是一份代码，里面是一个知识图谱预测，通过给定头实体和关系，预测尾实体，并且利用hit@1/3/10以及mrr来评判预测的效果。这里的头实体、关系、尾实体都是基于电商背景的。

我现在要应付一个面试，希望能够通过这份代码里展示的任务来编撰一段经历。这段经历的大致背景是：我在洋钱罐工作期间，开发了一些基于企业的特征，例如根据企业基本信息、企业社保信息等。我们希望利用这些企业特征来帮助判断用户是否逾期。除了正常的特征开发和子模型构建之外，我自己还利用企业和人员之间的关系，做了一些基于图神经网络的探索。我的思考过程经历过一些沿革：企业到企业的单纯的投资关系，再到企业与企业之间的抵押关系，再到人员与企业之间的任职、投资等关系。因为光用企业和企业之间的单种关系做图计算的话，最后能算出embedding特征的就不多，再关联上用户，再关联上逾期标签的，又更少了。所以只能不断地增加节点和边的种类，最后才能将这张网织得更大一些。我使用了若干种不同的gnn算法去将企业和人员做embedding，基本的原理其实我复用了当年那个github项目里面的东西，也是用图神经网络去做实体和关系的embedding，然后预测尾实体。最后的指标其实还是看的是否能够给风险建模带来增益，也就是基于普通的建模特征，新特征是否能够带来较为显著的AUC提升。当时的显卡资源就比在学校里的要好很多了。

然后针对面试常见的项目相关的问题，比如“大致介绍一下你怎么做的这个项目的？做这个项目的过程中遇到了什么困难（算法？工程？）并且你是怎么解决的？你这里的模型结构是怎么探索的？你做的这个最后有什么成果，跟学长的比起来效果几何？”等（如果还有别的问题，请不吝赐教），还有相关的八股比如“简要解释一下gcn, graphSage, gat, rgcn, rgat等算法的原理？你还知道什么图神经网络算法，介绍一下异同，为什么没有用上？”之类的（如果还有别的问题，请不吝赐教）。注意一下不能穿帮，比如我代码中用到了2023年前后不应该出现的算法、代码库和硬件设备，那就应该在介绍的时候规避掉。

这个项目的亮点就是我用了图神经网络。面试官肯定会问，为什么不继续采用transE之类的算法，请你给出一些合理的解释，包括但不限于“表现更好，增益更多”，但是要给出解释，为什么，可以从算法和数据角度来分析。

请从我提供的代码和代码运行结果，按照上述要求，编一段经历，并且给出一些面试题以及参考答案。我希望能够在这份项目中体现我对于知识图谱技术的深入理解。
